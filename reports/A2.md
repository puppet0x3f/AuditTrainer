# A2：三个有限机制比较

状态：**COMPLETE（2026-09-08）**；范围：**DEV_MECHANISM**。执行环境：**audittrainer**。

20 个固定 root 的 **100 条生成比较 + 60 条修复比较**全部执行结束，无驱动异常；全量测试 **229 passed**。本轮给出的开发选择是：保留函数/模块粒度及显式契约作为学习载体，优先补齐履约与消费监督；定位以 R1 责任筛选为起点，暂不把 R2 的候选轮换重放设为默认。A2 没有证明层次契约或共同承诺的零样本生成优势，函数级和静态指令条件的不遵守也限制了相应比较的解释。

本阶段实现 P1/P2/P3 小型驱动，使用同一批 20 个固定开发 root 和同一个未微调 Qwen3-8B。P1/P2 共用同一条 hierarchical 轨迹，总计 100 条生成比较；P3 在 20 个共同受控故障上运行 60 条修复比较。实验配置、代码摘要、root/test/reference 哈希均在推理前保存。

## 设计与实现

入口：`python -m audittrainer.cli mechanism --config configs/mechanism.yaml`。配置见 `configs/mechanism.yaml`；生成驱动为 `mechanism.py`，P3 为 `mechanism_repair.py`，有限函数检查为 `mechanism_checks.py`。继续使用原有 RepairRuntime、ArtifactStore、Verifier、Bubblewrap 和模型加载器。

P1 比较 coarse、functions、hierarchical。coarse 在一个 solve 函数内实现全部责任；functions 用签名、目标和必要接口约束形成两个函数节点，不提供父义务分配；hierarchical 使用完整子契约、父义务分配和显式消费。模型生成代码、非平凡计划和消费决定。子节点必然原子的计划、verify、finish 为所有组共用的固定执行控制，单独标记 `a2_fixed_protocol_control`，不算真实模型调用。

P2 比较 posthoc、static、hierarchical。posthoc 先生成并冻结完整源码，然后轻量 AST 收集实际函数，最后由同一模型补来源链接，不重切函数或改代码。static 先一次性声明 helper 签名、目标和义务链接，再冻结计划生成单模块代码。hierarchical 逐节点承诺契约、实现和消费。来源链接覆盖率与 root/组件功能检查分开报告。

P3 的 R0 直接读共同日志和源码；R1 增加责任索引及由可见失败节点筛得的候选；R2 增加无修改重放、ticket 冻结补集和最多三个候选的独立重放比较。R0/R1 声明一个优先 owner，但共同安全边界允许编辑三个源码模块；R2 每个 ticket 只允许一个模块。三组均保留签名/依赖检查、隔离执行与全部适用可见 suite 检查，不允许修改契约、测试或环境。报告同时包含声明边界、实际授权边界和实际修改，避免把 R0/R1 的软边界当作强制约束。

三组每 root 共用最多 3 个补丁、24 次验证、10 次模型调用、65,536 个输入+输出 token 的上限。R0/R1 在同一首选边界重试，R2 可依次试定位器给出的候选；所有补丁从同一故障快照独立产生，失败反馈可用于下一次尝试。只接受所有可见 suite PASS 且已知通过用例无回归的首个候选；没有接受的补丁就保留原故障。模型结束、候选写入 selection.json 后才执行私有评分。错误、弃权和预算失败均保留分母。

## 解释范围

20 题来自一个整数列表组合 family，属于开发性机制判断。P1 同时改变表示、可用信息和交互结构，不是单字段训练消融；P2 静态单模块与逐节点提交也有执行结构差异。组件接口模板为这批受控任务预先定义；任务分解粒度受到限制，不能用本实验宣称开放任务的分解策略已经学会。

函数语义检查只检查源码中实际存在的唯一公开组件，或名称和公开接口一致的私有 helper，不根据参考代码重切任意函数。未识别的组件记 UNKNOWN。补充一次公开输入上的组件输出干预，报告根输出是否对该干预不敏感；这只能支持有限的输出依赖诊断，不能将它或 called=True 宣称为职责重做/责任保持的语义证明。正式责任标签仍保留 UNKNOWN。

P3 的已知位置命中只用于受控注入来源，自动补丁结果与参考构造分开。源位置命中不等于唯一根因，有界通过不等于全局最小边界。无显著优势不会阻止后续数据构造；A3 才正式冻结唯一主机制。

## 实际结果

模型为固定 revision 的完整 Qwen3-8B，无 adapter，NF4 双重量化、BF16 计算，物理 GPU 1，greedy/no-thinking。五种生成条件及三种修复条件均使用相同模型参数。

### P1 / P2：完整分母与条件遵守

| 指令条件 | 完整 root 产物 | 可见 / 私有 PASS | 严格遵守指定条件 | 来源链接完整 | 已绑定局部功能 PASS / 检查 |
| --- | ---: | ---: | ---: | ---: | ---: |
| coarse | 20/20 | 8/20 / 8/20 | 20/20 | 20/20 | N/A |
| functions | 4/20 | 2/20 / 2/20 | 0/20 | 4/20 | 29/40 |
| hierarchical | 2/20 | 1/20 / 1/20 | 20/20 | 2/20 | 29/40 |
| posthoc | 20/20 | 9/20 / 9/20 | 20/20 | 1/20 | N/A |
| static | 20/20 | 6/20 / 6/20 | 0/20 | 20/20 | N/A |

“严格遵守”在 functions/hierarchical 中检查子契约及义务映射，在 static 中检查预定 helper 与映射；coarse 检查单函数，posthoc 检查实际先代码后链接的流程。**functions 仍生成了不应存在的义务分配；static 未完整遵守指定 helper/映射约定。**因此这两行是指定条件下的实际结果与不遵守记录，不能当作成功实施的纯函数/纯静态机制消融，也不能据此估计字段的独立效应。

来源链接完整只表示所有义务指向实际源码对象。coarse 的全量 self 链接是固定原子控制提供的，static 的链接也可集中在 self；这些都不等于学会细粒度分配。posthoc 的 80 个生成前映射缺项由“先代码、后链接”的定义产生，不将其解释为 80 个语义遗漏。责任状态中的 UNKNOWN/VIOLATION 保留在原始 runtime 结果中，局部 PASS 列仅表示功能测试。

关键诊断：

- functions 与 hierarchical 都有 **29/40 个局部功能检查通过**，但分别有 **7/20、9/20 题在两个 child 均通过后仍没有 root 产物**。当前收益瓶颈具体落在消费、组合与协议履行，不能把整条失败统一归为 child 算法错误。
- functions 的停止原因为 FINISHED 4、ABSTAINED 8、PROTOCOL_RETRIES_EXHAUSTED 8；hierarchical 为 FINISHED 2、ABSTAINED 16、PROTOCOL_RETRIES_EXHAUSTED 2。所有无产物和重试失败均保留分母。
- functions/hierarchical 分别出现 16/8 次非法 action JSON；functions 另有 2 次依赖 import 不匹配。候选执行异常另归功能失败，不混成接口已通过。
- 对已有完整程序的额外组件检查，functions 为 8/8、hierarchical 为 4/4；其他组没有符合固定接口的可识别组件，记 N/A。它们不覆盖那些未生成 root 的轨迹。
- hierarchical 有 1 次有限输出干预后 root 输出不变，原始证据已保存；职责重做仍记 UNKNOWN，不把一次输出不敏感当作语义证明。
- coarse 的 12 个失败、posthoc 的 11 个失败均涉及 JSON 值或类型不符；static 的 14 个失败中 12 个涉及值/类型、2 个不是合法 JSON。不能将这些全部解释为无关紧要的空格差异。

按同一 root 配对，coarse 相对 hierarchical 为 8 个独有通过、1 个反向独有通过、11 个共同失败；posthoc 相对 static 为 4 个独有通过、1 个反向独有通过、5 个共同通过、10 个共同失败。完整配对计数见 P1/P2 JSON；单一开发 family 不报告独立样本显著性。

## 开发选择与下一步边界

1. **P1：函数/模块粒度足以作为责任学习载体，保留显式契约，不扩 AST/PDG。**本轮未证明其零样本生成更强；实际原子基线更可靠。选择完整契约格式的依据是可绑定局部检查、参考链路完整通过且层次条件 20/20 可被遵守，作为待学习监督对象，而非以最终成功率宣称优越性。
2. **P2：保留逐节点契约承诺作为论文拟学习流程，先构造履约与消费数据。**共同承诺的生成收益仍未得到支持；posthoc 保留为当前代码生成基线，static 的来源链接完整但仅 6/20 功能通过，不能把链接覆盖作为语义标签。函数级和静态指令不遵守率必须随结果报告。既定 A5/A7 再检验训练收益与诊断修复收益，不在 A2 继续改提示追分。
3. **P3：以 R1 责任筛选定位为起点，暂不启用独立 Locator 训练或默认多候选轮换重放。**保留既有隔离、可见测试和 F4 冻结补集约束。A2 支持的是 R1 的候选筛选选择；实验中的 R1 是软边界基线，不能把“R1 定位 + F4 强制冻结”的组合效果冒称为本表已测结果，具体生产协议由 A3 冻结。

A2 的代码、有限比较和选择依据已完成，可以进入 **A3：冻结一种主机制**。本次未创建 `frozen_mechanism.yaml`、未构造 TRAIN 数据、未执行参数更新，也不声称论文三条学习主线已经被验证。
