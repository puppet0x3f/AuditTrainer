# B3 任务覆盖扩展：固定 3 根与轮换 12 根

状态：**COMPLETE（2026-09-14）**。
本轮只改变 RL 采样的任务覆盖，先完成用户建议的第一项独立对照。

**轮换 12 根 B3 为 52/60，固定 3 根 B3 与 B0 均为 51/60。**
轮换组相对固定组为 1 胜、0 负、59 平，原有三个任务没有退步。
但有效责任分配比较从 3/15 批次降至 2/15；新增成功来自分解被拒后重试原子实现，
本轮提供了小幅自然运行收益，尚未显示扩大覆盖增加了目标分配信号或改善了主动粒度选择。

问题是：在相同执行和更新预算下，扩大责任组合覆盖，能否增加有用的分解比较信号，并改善自然执行结果？
固定 3 根的 B3 使用已经完成的五轮训练链；扩展 B3 从相同的共同 SFT 检查点重新开始，逐轮采样自己的当前策略。
两组不是接续训练关系。旧对照的 135 条训练轨迹和 50 次更新复用，单独记录历史成本。

## 任务池与执行校准

任务与轮换顺序在新增模型运行前固定。全部 12 根为 TRAIN，保留原来的三个组合：图→库存、库存→账本、账本→库存。
新增四个兼容接口的组合为库存→图汇总、账本→图汇总、区间占用→按位置整除汇总、时间去重→按位置整除汇总。
另五根复用区间、矩阵、字符展开、路径前缀、多项式任务的原有准备/汇总语义，公开与组合任务相同的子契约目录。
它们覆盖字典、整数列表、字符串及嵌套列表的职责边界；不将参数或目录包装计为新的独立算法家族。

所有组件与独立 oracle 来自已有 TRAIN 实现。原有三根的任务定义逐项核对一致。
48 个固定参考计划已通过真实宿主注册；288 个组件/根用例的参考实现与独立 oracle 对照通过。
见 [任务检查](../runs/refinement/B3_coverage/task_checks.log)。

每根对 ATOMIC、pipeline、fused、parent_aggregate 各执行 4 次，共 **192 条校准轨迹**。
前两次和后两次构成两个预定种子块，分别观察方向是否重复。校准仅执行固定参考计划，不额外采集原始策略组。
全部任务、失败和分配均保留；参考计划不赋予模型采样概率，不进入 RL 更新。
校准用于描述执行器支持和责任分配差异，不预先假定每个新增任务都提供优势信号。

校准实际完成 **192 条轨迹，161 条功能通过**；12/12 根在两个种子块中均存在成功分解，
4/12 根在不同合法分配之间重复观察到同方向差异，10/12 根的 ATOMIC 至少通过 3/4。
两个 worker 的规划器与 F01 指纹前后一致，原始策略采样数为 0，见 [校准结果](../runs/refinement/B3_coverage/calibration/result.json)。

参考计划中的差异是否会被模型采到并用于更新，仍由后续原始策略组检验。
本批原有库存→账本四种计划都为 2/4，也说明旧校准的优势方向不能被视为无噪声的固定标签。

## 固定训练对照

| 条件 | 固定 3 根 B3 | 轮换 12 根 B3 |
| --- | --- | --- |
| 初始化 | 共同结构 SFT | 同一共同结构 SFT |
| 每轮状态数 | 3 | 3 |
| 轮数/连续 optimizer 更新 | 5 / 50 | 5 / 50 |
| 候选续跑 | 120 | 120 |
| 独立自然基线 | 15 | 15 |
| 不同 RL 根任务 | 3 | 12 |
| 数据来源 | 已完成训练链的原始记录 | 当前策略逐轮新采样 |

轮换第 1、5 轮使用原有三根；第 2–4 轮分别使用其余九根，每个新增根采样一次。
每状态仍为 1 个 ATOMIC、3 个条件 SPLIT 正文，每候选 2 次续跑，以及 1 次独立自然基线。
非法、重复和截断样本均保留。逐轮种子与固定 3 根的对照匹配，任务变化后的候选文本无需相同。

B3 统一优势、`R=(1-v)y-0.2v`、固定 F01、`max_depth=1`、关闭修复及全部执行预算不变。
学习率 1e-6、clip 0.2、KL/SFT 权重各 0.02、全局 scale 1/256、梯度范数上限 1，
每次更新累积 3 根。行为模型逐轮刷新，KL 始终参照共同 SFT，Adam 状态与保持示范顺序跨轮衔接。
没有新增独立 SFT 阶段，也未改变续跑次数、基线平均方式或模式权重。
训练采样可通过已有的根分片接口在多个 GPU 并行；每根的全局索引、种子、候选数和续跑数保持一致。
并行只缩短等待时间，所有分片完成后才进行一次轮次更新，不以墙钟时间比较算法效率。
首轮实际核对：三个根的全部 Q 值，以及九个 SPLIT 候选的输出 token，都与固定 B3 原首轮一致；
三个采样 worker 的权重冻结检查通过。扩展覆盖从第二轮开始。

## 实际训练信号

两组均保留 15 个根状态批次、45 个原始 SPLIT 候选。新增 135 条训练轨迹及 50 次连续更新已经全部完成。

| 信号 | 固定 3 根 B3 | 轮换 12 根 B3 |
| --- | ---: | ---: |
| 原子与平均分解回报不同 | 9/15 | 10/15 |
| SPLIT 候选回报不同 | 7/15 | 10/15 |
| 已注册且有局部 oracle 的不同完整分配回报不同 | 3/15 | 2/15 |
| SPLIT 初始注册成功 | 39/45 | 36/45 |
| 已注册且有局部 oracle 的 SPLIT | 37/45 | 34/45 |
| 已注册且匹配四种参考分配的 SPLIT | 29/45 | 25/45 |

轮换组的两个有效分配比较来自首轮库存→账本，以及第三轮账本→图。
第二轮时间任务虽出现 1.0 对 0.0 的候选回报，但两个低分候选初始注册失败；
第四轮字符任务两个结构化动作完全相同的 `parent_aggregate` 候选分别为 0.0、0.5，
属于相同责任分配在不同续跑种子下的波动，不能当成不同分配的质量差异。
诊断对同一种完整分配先平均，训练保留每个原始候选及其实际回报。

**本轮扩大覆盖增加了一般回报差异，却没有增加已注册、局部检查覆盖的责任分配比较。**
这将校准中的可用差异与策略实际采样得到的学习信号区分开来。
第五轮三个根的全部候选回报分别为全 1、全 0、全 1，恰好等于各自独立基线；
因此这一轮 B3 奖励优势全部为零。仍按配对预算执行 10 次更新，其中保留项及 Adam 历史状态仍可能影响参数。
固定 B3 原第五轮也为零优势，不将两组的全部 50 次更新称为 50 次有非零奖励信号的更新。

### 新增成功来自哪里

相对固定 B3 唯一新增的成功是区间→整除汇总，种子 `1343715`。
固定 B3 的 SPLIT 初始注册成功，但最终功能失败；轮换 B3 的初始 SPLIT 因 `MISSING_OBLIGATION_OWNER` 被拒，
随后重试 ATOMIC 并通过。B0 在这个种子上也走了分解被拒、重试原子的成功路径。
见 [固定 B3 轨迹](../runs/refinement/B3_coverage/evaluation/B3_fixed/natural/train_transfer_intervals_matrix_03/repeat_02/runtime/trace.jsonl)
与 [轮换 B3 轨迹](../runs/refinement/B3_coverage/evaluation/B3_rotate/natural/train_transfer_intervals_matrix_03/repeat_02/runtime/trace.jsonl)。

相对 B0 唯一新增的成功来自路径任务，种子 `1349713`；两个 B3 都通过该种子，B0 协议重试耗尽。
轮换 B3 也是初始计划失败后注册 ATOMIC 完成。
因此，**本轮的自然通过率净增 1 条是真实的，但不能将其解释为学会了更好的初始合法分解或主动停止决策。**
完整后续奖励包含协议重试恢复的效果，本轮保持这一既有规则不变。

### 计划分布诊断

重点库存→账本的固定评分与新条件探针结果：

| 诊断 | B0 | 固定 B3 | 轮换 B3 |
| --- | ---: | ---: | ---: |
| 根 SPLIT 概率 | 20.18% | 20.18% | 20.18% |
| 原优选/合并正文固定文本相对概率比，相对 B0 | 1.00× | 12.50× | 1.76× |
| 新探针匹配 parent_aggregate | 7/12 | 8/12 | 8/12 |
| 新探针初始注册成功 | 11/12 | 12/12 | 11/12 |
| 新探针注册且有局部 oracle | 9/12 | 10/12 | 10/12 |

轮换组在重点根上的固定文本评分改善较小，但本批 `parent_aggregate` 采样数与固定 B3 相同。
这两个指标衡量不同对象：固定文本概率比不等于整类语义分配的概率，条件计划探针也没有执行续跑。
根 SPLIT 概率基本未变，后续若研究模式权重，仍需单独检查实际加权梯度贡献。

本轮是同一训练随机链下的 TRAIN 覆盖对照；新增九根相对固定 B3 未参与该 RL 更新，
但其中的算法组件可能参与过原有 SFT，且全部属于 TRAIN。结果不作为未见任务泛化或多训练种子稳定性结论。
增加候选/基线续跑、调整模式权重及多训练种子未见任务评测属于后续独立实验。

本轮支持继续将 B3 作为主线，同时保留固定与轮换两组对照。
按原顺序，下一项应独立检验增加候选续跑与基线平均能否提高回报估计的稳定性，
并沿用初始计划注册与重试恢复记录，区分分配质量和恢复路径带来的收益。
本次不继续扩大任务数量，也未混入该项设置变化。

## 实现与复现

配置：[训练与评测](../configs/refinement_coverage.yaml)、[执行校准](../configs/refinement_coverage_calibration.yaml)。
实现：[覆盖对照入口](../src/audittrainer/refinement_coverage.py)，复用既有课程校准、多轮训练和评测器。

```bash
python -m audittrainer.refinement_curriculum prepare-transfer --config configs/refinement_coverage_calibration.yaml
python -m audittrainer.refinement_curriculum collect --config configs/refinement_coverage_calibration.yaml --shards 2 --shard-index 0
python -m audittrainer.refinement_curriculum collect --config configs/refinement_coverage_calibration.yaml --shards 2 --shard-index 1
python -m audittrainer.refinement_curriculum report --config configs/refinement_coverage_calibration.yaml
CUDA_VISIBLE_DEVICES=0 python -m audittrainer.refinement_coverage run --collection-gpus 0 1 2
python -m audittrainer.refinement_coverage evaluate --method B0
python -m audittrainer.refinement_coverage evaluate --method B3_fixed
python -m audittrainer.refinement_coverage evaluate --method B3_rotate
python -m audittrainer.refinement_coverage report
```

使用 audittrainer conda 环境、`OMP_NUM_THREADS=4`，用 `CUDA_VISIBLE_DEVICES` 选择设备；两份校准 shard 使用不同设备。
重现实验使用新的输出和数据目录；本轮固定对照来源为 [原 B3 训练记录](../runs/refinement/PR1C_multiround/B3/training_report.json)。
