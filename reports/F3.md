# F3：递归、源码版本、显式消费与父节点组合

范围：**SMOKE_ONLY**。验收日期：2026-09-07。环境：Conda `audittrainer` / Python 3.11.14。

## 实现内容

- `runtime.py`：逐节点状态与递归栈、稳定 child/contract ID、深度优先调度；所有节点共享同一
  Policy、verifier、trace 与 root 调用/token/验证预算。WAIT_CHILD 不调用 policy，返回后进入 RESOLVE_CHILD。
- `schema.py`：Consumption 记录，以及 NodeResult 中的责任状态和未完成委托信息。
- `artifacts.py`：不可覆盖的源码版本、精确版本/hash 解析、传递依赖闭包、受审查的导入格式，
  物化 `nodes/`、`manifest.json` 和固定 `entry.py`。生成业务代码始终来自 policy 的 write_code。
- `sandbox.py`、`_sandbox_runner.py`：在 F2 隔离环境中运行 bundle，约束直接 child 导入，
  使用公开函数的执行帧记录 consumer→child 调用次数。
- `verifier.py`：fingerprint 纳入完整 bundle，记录 selected/linked/called 和调用覆盖完整性。
- `cli.py`：新增 `smoke --stage f3`；`fx02_range_sums.json`：新增三层区间求和 fixture 与独立审查的局部/root suites。
- `tests/test_runtime_f3.py`：24 项 F3 检查；新增 fixture 登记到 `roots.jsonl` 的 SYN_FIXTURE 分区。

## 异常路径与责任检查

| 场景 | 观测 |
| --- | --- |
| child 功能 FAIL | 正常返回；默认 consume 被拒，显式 accept_unverified 后记录 known_failed_consumed，组合失败仍如实记录 |
| child 无匹配 local oracle | UNKNOWN 可显式消费；root 可独立通过，但 child 不继承 root 的 PASS |
| child runner ERROR | 不允许按未验证候选消费；保留 ERROR，未运行的其他 child 记 NOT_FINISHED |
| reject child 后 parent 重做算法 | incoming contract 不变，委托义务仍未完成；即使 root 功能 PASS，也保留责任 VIOLATION |
| 对失败 child 请求修复 | 原 child 在同一契约、artifact 和证据下回到 REVIEW；请求和指令进入 observation，不增加节点 |
| 再次请求同一 child 修复 | 受每条边 1 次上限约束，不重置 root 预算 |
| 超深度、超节点或超 child 数量的 SPLIT | 整个动作被拒，没有部分创建子节点；仍可 ATOMIC/abstain |
| root policy 预算耗尽 | 全树停止；不会为每个 child 重新获得调用预算 |
| 旧版本、错误 hash、非当前 child、伪造证据 | consume 被拒，当前待处理 child 与消费记录保持不变 |
| 后代发布新版本 | consumer 的传递依赖证据失效；旧源码和旧证据继续保留；不能用旧证据 finish |
| 保存 parent 前依赖已过期 | 写入前拒绝，不遗留半成品 artifact |
| child import sibling | 静态拒绝未消费模块；动态 importlib 调用也检查直接 child 边界 |
| consume 但不 import/call | selected=true，linked=false，called=false |
| import 但不 call | linked=true，called=false |
| 调用后丢弃结果并重算 | called=true，dependency_supported=UNKNOWN；不会误报消费语义成立 |

版本失效测试通过宿主存储 API 发布新版本，以检查不可覆盖和绑定失效；这不被计为模型修复成功。
每个成功保存的工作区只包含该节点及其明确选择的传递依赖，不包含未消费 sibling 或测试 oracle。

## 完成边界

F3 已满足 `child 真实验证 → parent 显式消费 → parent 自行生成组合 → root 真实验证` 的验收标准。
本次修正了三个接口问题：未执行节点不再继承 root 的终止理由、基础设施 ERROR 不能按未验证候选消费、
保存 parent 前先检查整个依赖闭包，避免拒绝动作留下半成品源码。当前没有阻塞 F3 的工程问题。

`request_child_repair` 已完成重新调度与证据传递；当前 child 可重新验证、提交或弃权。
localize、ticket、授权补丁、回滚及计划修订按路线在 F4 实现，不允许用 write_code 覆盖已提交版本。

调用记录说明指定用例中公开函数被执行，不证明返回值被业务逻辑使用，也不证明全部自然语言责任履行。
导入检查和调用跟踪用于当前 Python 协议审计；不宣称对主动篡改 Python 运行时的程序具有不可伪造性。
外层候选执行继续使用 F2 的 Bubblewrap 隔离与资源限制。全部数据均为 SYN_FIXTURE，尚未接入真实 LLM 或训练。
