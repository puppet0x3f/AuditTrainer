# F7：真实 QLoRA SFT 验收

2026-09-07，**COMPLETE / SMOKE_ONLY**。在 `audittrainer` 环境对完整公开 Qwen3-8B 执行真实 QLoRA，
完成参数更新、adapter/tokenizer 保存，以及全新量化底座上的磁盘重载前向核对。

## 实现

- [tokenize_sft.py](../src/audittrainer/tokenize_sft.py)：直接编码 F6 保存的 system/user messages，
  固定 `enable_thinking=False`，将完整 canonical action JSON 与 EOS 作为 target。
  prompt 与右侧 padding 的 labels 为 -100；目标不截断，EOS 与 PAD 同 ID 时仍保留 EOS 监督。
- [train_sft.py](../src/audittrainer/train_sft.py)：YAML 继承、身份/数据分区核对、有限课程采样、
  QLoRA 加载、逐样本平均损失、参数/梯度检查和保存后重载。
  Qwen3 的 `logits_to_keep` 只投影下一 token 的目标预测位置，避免为长 prompt 生成完整词表 logits。
  真正的因果 shift 与全序列实现对照通过；这不改变训练目标。
- `ActionSFTTrainer.model_accepts_loss_kwargs=False`，不使用总 target token 数缩放样本平均损失。
  在当前 Transformers 4.57.6 上，对完整和不足量累积窗口、大小不等的最后 microbatch，
  实际 SGD 更新均与一次直接样本平均更新对照一致。
- [sft_smoke.yaml](../configs/sft_smoke.yaml) 继承 [sft_main.yaml](../configs/sft_main.yaml)。
  `final_only` 转为最后一步保存完整 checkpoint，`no_effect_gate` 转为不运行能力评估门禁。

## 实际运行

在项目根目录执行；命令直接使用 `audittrainer` 环境的解释器：

```bash
CUDA_VISIBLE_DEVICES=1 OMP_NUM_THREADS=4 /home/lc/.conda/envs/audittrainer/bin/python -u -m audittrainer.train_sft --config configs/sft_smoke.yaml > runs/f7_smoke_console.log 2>&1
```

模型为 `Qwen/Qwen3-8B`，revision `b968826d9c46dd6066d109eabc6255188de91218`，
原始参数量 8,190,735,360。A0 已核对全量权重摘要，F7 复核分片大小及非权重身份文件摘要。
没有升级依赖：Torch 2.10.0、Transformers 4.57.6、PEFT 0.18.1、Accelerate 1.14.0、bitsandbytes 0.48.2。

物理 GPU 1 为 RTX 5880 Ada。使用 NF4 双重量化、BF16 计算、梯度检查点，
LoRA r=16 / alpha=32 / dropout=0.05 / all-linear，batch=1、梯度累积=4、seed=42。
试加载 GPU 3 时进程被系统 SIGKILL，原因未确定；GPU 1 的完整加载、训练和重载均通过。

## 数据与课程

输入为 F6 的 [smoke.jsonl](../data/sft/smoke.jsonl)，SHA256：
`dbb0107d802096f73042c608886855b8cbe384bda54c1b9fb38755fd87c74a05`。
32 条、4 个 root、2 个 family，均为 SYN_FIXTURE；22 条 RESPONSIBILITY_SUPPORTED、10 条 PROTOCOL_ONLY。
每条完整序列长度为 1,490–3,804 token，均满足 4,096 上限。离线证据和 meta 不进入输入。

前两步按 D_IMPL/D_CONTROL=80%/20% 采样；其余按 D_PLAN/D_IMPL/D_COMPOSE/D_CONTROL=30%/40%/25%/5% 采样。
每次先选 bucket，再均匀选 root，再选该 root 的动作，固定 seed 并保存实际顺序。
40 次有放回抽样涉及 **19 条不同样本**；实际计数 D_IMPL 18、D_CONTROL 3、D_PLAN 8、D_COMPOSE 11。
D_COMPOSE 含 5 次 consume、6 次父节点 write_code。共监督 3,095 个目标 token，包含 EOS 与重复暴露。

这是有限 smoke 抽样，不声称 32 条数据均被训练使用。正式 TRAIN 配置最多抽取一个数据集大小的样本量；
训练入口拒绝开发/验证/SEALED 分区，以及 FUNCTION_ONLY 对照混入核心责任训练。
