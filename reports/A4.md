# A4：可追踪责任训练集 pilot

环境：`audittrainer`。使用冻结主机制，运行协议为 `at-v3r1-a3.2`，数据检查协议为 `at-data-check-v1`。

## 数据范围与构造

本轮新建 50 个 TRAIN root，分为账目、区间、图、库存、文本、分块、矩阵、时间、多项式、路径
10 个任务族，每族 5 个参数配置。任务、root/family 分区、可见与私有 oracle 在正式采集前登记。
这些是可审查的参数化训练题；不声称 50 个独立任务族或新的评测 benchmark。
原有 6 个 SYN_FIXTURE、5 个 DEV_ENGINEERING、20 个 DEV_MECHANISM 保留原分区，未混入训练。

每题提供两种组件职责以及完整输入/输出契约。可见输入包括空边界与非空案例，另有四组私有边界/组合
输入；root 和局部 suite 按完整契约适用。独立 oracle 使用另一份算法实现，候选始终经现有隔离 runner
真实执行。模型只见在线 VISIBLE，TRAIN 私有检查在终止后用于标签，另计成本。

每个 root 的同一初始父状态运行三种合法计划：ATOMIC、prepare/aggregate 两 child、compute 单 child。
实现与组合统一由 `a4_E_ref_v1` 执行，配额相同、实际成本分别保存；不从一次成功差异推导粒度偏好。
示范含局部变量改名、合法 helper，以及矩阵/分块的不同正确算法。`reviewed_reference` 与真实
`natural_model_rollout` 明确区分，程序生成的示范没有冒充模型调用。

自然采集为有限分层诊断：每族固定参数 3 的 root，K=1，共 10 个 root。
50-root pilot 的主数据来自可审查示范，符合“自然正例不足时补充示范”的路线。
不以私有得分选择自然采样任务，也不把示范成功率当作底座能力。

## 对照与证据

每族选择一个 root，先执行合规 baseline；stale 对照额外用真实 v1 失败→ticket→v2 修复的 baseline。
再分别施加一个变换，共六类：

| 变换 | 干预与判据 |
| --- | --- |
| omit_output | parent 删除一个必需输出字段；单列功能失败 |
| move_algorithm | prepare 算法移入 parent、child 仍被选择；检查功能匹配与责任违反 |
| bypass_child | child 被调用后丢弃结果并重算；调用证据和独立源码证据分别记录 |
| stale_artifact | 实际 v2 返回后选择磁盘上存在的 v1；由 host 拒绝精确版本违约 |
| wrong_argument | aggregate 接收空映射而非 prepare 结果；单列功能失败 |
| expand_owns | 保持义务分配不变却扩大 child.owns；记录契约违规与局部 UNKNOWN |

每对保留原始/变换后 action、源码、root/局部检查、接口及预算、独立责任证据和标签强度。
根功能匹配且 child 契约相同的违规才进入 `FUNCTION_MATCHED_RESPONSIBILITY_VIOLATION`。
不同执行的 evidence 中存在计时差异，因此这里不冒称已形成同一完整 observation 的 DPO 对；
`preference_ready=false`，A6 若启用 DPO 仍须构造严格同输入偏好。

责任正例采用 A3 允许的可信构造规则与独立执行证据。SOURCE、契约和分配均绑定到真实事件，
审查器不读取“这是正例/负例”的生成标签来决定 verdict。自由模型程序无法确认时为 UNKNOWN。
分层审核表记录 PLAN、IMPLEMENT、CONSUME、PARENT_WRITE、未知与受控负例。
首次导出时审查来自程序规则及 Codex 源码复核，**逐事件真人标注数为 0**；原表保留当时的
`NOT_PERFORMED`。随后用户报告人工复核完成、未发现问题；最新验收与二次复核见文末。
用户的总体复核反馈与机器逐事件标签分别记录，不回填不存在的逐条真人标注。

## 本阶段修复的协议 bug

3.1 只展示剩余总节点数，没有展示每节点最多 3 个 child。早期自然轨迹连续提出四 child，
而反馈也未明确指出该限制。修订只增加 `budget_remaining.child_slots` 与具体拒绝信息；
action、prompt renderer、oracle、模型 revision、采样温度、候选/补丁/执行预算均保持原值。

主机制补丁版本为 `a3-main-v1.1`、运行协议递增到 3.2，数据检查协议不变。
旧版本共 242 个有 trace 的运行归档至 `data/raw_traces/a4_protocol31_archive/`，
按 run_id/event_id 列于 `runs/a4/protocol_bug_impact.json`；未导出旧样本，不回填旧输入。
所有本轮最终训练来源重新执行。早期与修订后的自然采样集合不同，不作前后性能比较。

第一次物理 GPU 3 权重加载被系统 SIGKILL（137），未返回模型调用；保留失败请求与日志。
实际自然采集使用物理 GPU 1、Qwen3-8B NF4/BF16。中断时未返回的调用不伪造 token 统计。

## 实际结果与产物

**A4 pilot 已完成，正式 TRAIN 导出 2,240 条动作，覆盖全部 50 个 root。**

| 数据桶 | 动作数 |
| --- | ---: |
| D_PLAN | 460 |
| D_IMPL | 320 |
| D_COMPOSE | 400 |
| D_CONTROL | 1,060 |

其中 1,180 条为 RESPONSIBILITY_SUPPORTED、1,060 条为 PROTOCOL_ONLY；
820 条原始事件未进入 SFT，包括 600 条 host 事件，以及功能失败、责任违反、未验证消费、
FUNCTION_ONLY、修复动作等。未发生半条 action 截断或超长样本静默切片。

- **分解示范**：150 条全部 FINISHED/PASS，150 个 root plan 均满足正例证据标准。
  50 个 root 的三种计划起点逐字段相同，executor 身份只有一个；没有生成计划优劣偏好。
- **受控对照**：60 对全部执行，20 对功能失败、20 对功能匹配责任违反、20 对协议/契约违反。
  另有 20 条 baseline（含 10 条先修复再消费的 baseline），对照部分共 80 条真实轨迹。
- **自然采样**：10 条全部弃权、没有完整 root 产物。每题都提交四 child，超过已展示的
  child_slots=3，收到明确反馈后弃权；这些动作不作为合法计划或实现正例。
  共 20 次真实模型调用，39,318 输入、10,766 输出 token；只有 10 条据实弃权进入协议监督。
- **审核**：2,460 个策略事件逐条留档，形成 90 条分层审查记录；程序语义 UNKNOWN 与
  PROTOCOL_ONLY 分开表示，不能把控制动作正确解释为代码责任已被证明。
- **加载与采样**：2,240 条全部通过正式 TRAIN loader 和完整 action 分词检查。
  固定种子生成 2,240 次抽样，覆盖 50 个 root、953 个不同 sample_id；140 个计划 optimizer step，
  实际抽样 D_PLAN=549、D_IMPL=1,048、D_COMPOSE=471、D_CONTROL=172，目标 token 暴露 258,254。
  这是一轮有放回的有限抽样，未执行项目模型训练。
- **测试**：`audittrainer` 环境全量 **247 passed、15 warnings**（222.03 秒），一次通过；
  警告来自既有 Torch/PEFT 路径。新增 11 项 A4 检查覆盖独立 oracle、root 隔离、
  同状态三计划、真实旧版本、功能匹配违规、UNKNOWN 与私有证据隔离。

新协议有效数据的执行成本另行保存：示范 1,350 次参考策略动作、300 次在线验证和 300 次离线验证；
对照及其 baseline 1,090 次参考策略动作、260 次在线验证和 210 次离线验证。
它们共执行 3,038 个用例（在线 1,049、离线 1,989），不计作模型调用。
归档的旧协议执行和加载失败保留独立日志，不并入以上有效数据统计。

机器汇总见 `runs/a4/result.json`。全量日志为 `runs/a4/pytest.log`，标签、导出、采样与自然轨迹日志
分别为 `labels.log`、`export.log`、`schedule.log`、`collection.log`。

- `data/train/pilot/selection.json`：50-root 来源与任务族，逐任务的规范化题目、参考源码与 oracle。
- `data/manifests/roots.jsonl / tests.jsonl`：新增 TRAIN 的 root/family 与测试登记。
- `data/raw_traces/a4/`：新协议示范、自然采集、对照、源码版本、真实事件和独立 supervision。
- `runs/a4/evidence_audit.jsonl / stratified_review.jsonl`：逐事件判据、排除原因与分层审查表。
- `runs/a4/plan_candidates.jsonl / contrasts.jsonl`：同父状态计划记录、执行成本及受控对照标签。
- `data/sft/train.jsonl` 与 manifest/rejected：四个桶的正式 TRAIN 动作和全部拒收原因。
- `runs/a4/sampling_schedule.jsonl / schedule_report.json`：主 SFT 的真实有限抽样顺序、root/桶/目标 token 暴露。

## 数据验收与二次复核（2026-09-08）

**数据验收通过，可以进入 A5 的核心训练与能力隔离。** 用户在本次对话中报告
“我复核完没什么问题”，Codex 随后重新对照任务契约、组件源码、原始轨迹、执行证据和最终导出，
未发现需要修正训练标签、删除样本或阻止 A5 的问题。

| 本次复核范围 | 结果 |
| --- | --- |
| 10 个任务族的 prepare/aggregate 语义及三种组合方式 | 实现符合各自契约；parent 传递并使用 child 结果，没有在合规示范中重做 child 算法 |
| 2,240 条导出、240 条来源轨迹、2,460 个策略事件 | 分区、原始动作、版本、责任标签绑定及收录/排除一致；未发现未来或私有证据进入输入 |
| 150 个真实 root plan：ATOMIC/pipeline/fused 各 50 | 义务覆盖与分配一致，同 root 起点相同，均有实际执行支持 |
| 60 对负例：六类各 10 | 功能匹配违规、功能失败、协议/契约违规分开成立；已标记的违规动作未进入正例 |
| 原 90 条分层记录的控制动作与 UNKNOWN | 弃权、失败后提交只属于 PROTOCOL_ONLY，不能被解释为分解或代码责任正例 |
| 50 个 root 各补充 2 个有效输入，检查 prepare/aggregate/compute/solve，共 400 次函数调用 | 输出符合已审查 oracle，输入未被修改；覆盖现有 plain、renamed、helper、alternative 示范 |

复核发现原抽查表按决策 mode 取首条记录：PLAN 栏实际是自然轨迹的 abstain，
CONTROLLED_NEGATIVE 栏只选到了 bypass_child。因此，**仅凭那 90 条不能认定抽查已覆盖真实计划和六类负例**。
本次已补查全部 150 个 root plan 和 60 对负例，补齐当前数据的覆盖；这是原抽查表的覆盖缺口，
不是训练标签错误。原表及原始导出保留，补充结果另存。

补充调用是对已审查参考源码的进程内诊断，不计入原始隔离执行成本，也不追加为训练数据或正式评测。
