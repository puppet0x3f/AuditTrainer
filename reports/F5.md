# F5：真实 LLMPolicy、统一输入与上下文预算

范围：**SMOKE_ONLY**。日期：2026-09-07。环境：Conda `audittrainer` / Python 3.11.14。

## 实现

- `policy.py`：本地 Transformers `LLMPolicy`，一次生成一条动作，全部递归节点和 batch roots 共享一个模型实例；支持记录 base 和可选 PEFT adapter 身份。
- `prompts.py`：固定系统协议，按 allowed_actions 从执行 schema 生成 JSON Schema；统一 `render_messages` 与 Qwen no-thinking chat template。
- `schema.py`、`runtime.py`：逐事件保存真实 messages、完整 prefix、输入/输出 token ID、输出配额、生成配置、模型身份、原始响应及解析结果。
- `cli.py`：`rollout --policy base` 从已登记的 SYN_FIXTURE/DEV_ENGINEERING roots 运行完整 F4 runtime；保存 batch 配置与逐 root 终态。
- `tests/test_policy_f5.py`：17 项接口检查；测试替身显式标记 `test_fake`，与下面的真实 Qwen 运行分开。

模型策略仅接收 runtime 的决策前 observation。fixture 的 script、reference、故障标签和未来结果不进入 prompt；
private evidence 被拒绝。没有模型失败后切换 ScriptedPolicy 的路径。

模型输出不提取代码围栏、不补 JSON、不替模型重写 source。host 再次从 raw_text 严格解析动作；
非法/截断动作只产生拒绝事件，下一次 observation 提供结构化错误反馈，最多重试一次。
终止 EOS 保留在 output_token_ids 和 token 用量中，解析文本仅去掉这一终止 token。

8192 token 上下文先为当前允许动作的最大输出配额留空间。只按确定性规则省略重复证据绑定与重复 evidence；
完整契约、当前源码、失败用例、待处理 child 的接口/源码和 ticket 不截断。
仍超长时保存 CONTEXT_OVERFLOW，root token 不足则保存 TOKEN_BUDGET_EXHAUSTED，均不会继续调用模型。
模型调用异常保存 MODEL_ERROR、实际输入和 unavailable 用量，不伪造生成 token 数。

## 实际模型运行

```bash
OMP_NUM_THREADS=16 conda run --no-capture-output -n audittrainer python -m audittrainer.cli rollout \
  --policy base --split SYN_FIXTURE --limit 2 --max-policy-calls 24 \
  --device cpu --run-dir runs/f5_base_smoke_cpu
```

使用完整 BF16 `Qwen/Qwen3-8B`，共 **8,190,735,360** 个参数；没有量化、adapter 或参数更新。
底座 revision 为 `b968826d9c46dd6066d109eabc6255188de91218`。Transformers 4.57.6 / Torch 2.10.0+cu128。
`enable_thinking=False`；seed=42，temperature=0.7、top_p=0.8、top_k=20；每个 root 最多 24 次策略调用。
配置、根任务顺序和生成设置在运行前固定并保存，未以功能 PASS 为依据反复调整提示词。

身份依据为 A0 的完整文件摘要核对；F5 再检查权重分片大小、非权重文件摘要和 chat template 摘要，
不把这一检查说成重新计算了全部 16 GB 权重的 hash。
实际身份见 [model_identity.json](../runs/f5_base_smoke_cpu/model_identity.json)，
运行前配置见 [request.json](../runs/f5_base_smoke_cpu/request.json)。

总计 **10 次真实生成、25,995 输入 token、923 输出 token**，两个 root 都保存了 TERMINAL 结果。
FX01 代码独立处理整数求和和空输入，六个可见用例通过。
FX02 将字符串输入当作字典，触发 `TypeError: string indices must be integers, not 'str'`；
模型依据可见证据选择 `localize(NODE, N0, OWNER_MODULE)`，host 重放后签发 T1。
随后模型的 repair 试图声明 `N0 ← N0` 依赖边，被 `UNAUTHORIZED_REBIND` 拒绝。
下一次真实调用收到该结构化反馈并选择 abstain；原 v1 代码、FAIL 证据和被拒绝的原始输出均保留。
没有接受这次补丁，也没有把弃权或 CLI 退出码 0 当成功能成功。

## 接口验收

全量测试：`conda run --no-capture-output -n audittrainer python -m pytest -q`，**148 passed in 100.22s**。
最终 F5 定向检查：`python -m pytest -q tests/test_policy_f5.py`，**17 passed in 8.89s**。

检查覆盖：真实本地 tokenizer 的 no-thinking 文本/token 一致性、最大允许动作配额、完整必需输入不截断、
确定性证据压缩、私有信息隔离、严格 JSON 与截断拒绝、唯一错误重试、上下文/总 token 预算、
模型异常保存、输入输出 token 守恒、PASS/FAIL 提交、共享模型跨全部 4 个递归节点的 19 次接口调用，
以及 base CLI 不构造 ScriptedPolicy、空 DEV_ENGINEERING 分区不加载模型。

这些接口测试使用明确标识的测试替身和真实隔离 verifier，不能充当真实模型能力证据。

## 设备情况与完成边界

GPU 3 上的加载进程反复收到 SIGKILL（退出码 137），系统没有给出可确认的 OOM 原因；
GPU 1 的诊断加载受到其他任务占用影响而 CUDA OOM。没有终止其他任务。
因此正式 smoke 显式选择 CPU，仍使用标准 Transformers 加载器和同一份完整公开权重。
GPU 加载尝试未发生模型生成，不计入上述自然轨迹；它们的目录保留运行前 request。
分块读取只用于定位加载问题，未保留到最终实现。

**F5 已完成**：真实模型与责任 runtime 接通，成功、可见失败、边界拒绝和弃权都能保存为可复核结果。
功能 PASS 仅由固定可见 suite 支持；责任状态单独记录。
F6 的训练数据导出、F7 参数更新、F8 新 adapter 回接和正式能力评测均不属于本次完成范围。
