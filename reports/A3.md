# A3：冻结一种主机制

日期：2026-09-08。环境：`audittrainer`。主机制版本 `a3-main-v1`；运行协议
`at-v3r1-a3.1`；数据与检查协议 `at-data-check-v1`。

## 固定的研究选择

| 对象 | 唯一主方案 | A2 依据及结论范围 |
| --- | --- | --- |
| 责任边界 | 层次契约，每节点一个函数/模块所有权 | 可绑定局部检查，作为责任学习载体；A2 未证明零样本生成优势 |
| 契约形成 | 逐节点承诺，模型自主选择 ATOMIC/SPLIT | 保留三主线学习对象；先补固定契约履约和显式消费/组合监督 |
| 定位 | R1 责任筛选，共享 policy 选择目标 | A2 定位 20/20、私有修复 19/20；不启用独立 Locator 训练或默认候选轮换 |
| 修复 | F4 ticket、隔离候选、补集冻结、可见测试接受/回滚 | 保留已验收的边界执行；A2 的 R1 为软边界，此组合的性能未在 A2 测量 |
| 学习 | 固定公开 Qwen3-8B 的共享 QLoRA SFT | 延续已跑通的训练器，先履约再分解/组合；DPO、RL 暂不启用 |

历史 A2 的比较 arms、专用提示、固定两 child 控制和 greedy 配置留在机制实验驱动，
后续主运行使用标准共享 observation renderer。候选筛选按当前、契约绑定的 FAIL 证据找 owner，
child 优先于当前节点；排除过期失败，最多三个候选。没有适用 FAIL 时保留当前节点供明确决策，
不把 UNKNOWN 当作 failed child。模型仍需输出 `localize` 和 `repair` 动作。

保留 F4 单个证据锚点的稳定性重放；关闭的是 R2 的额外候选比较重放与自动轮换。
筛选本身不执行测试，ticket 后全部执行计入 root 预算。

## 实际交付

- `configs/frozen_mechanism.yaml`：可直接传给现有 runtime 入口的完整配置；记录动作、observation、
  renderer/tokenizer/template 身份、责任格式、oracle、修复、数据分区与训练入口。
- `docs/data_check_protocol_v1.md`：逐桶正例证据、功能/责任负例区分、UNKNOWN、可见/私有隔离、
  root/family 继承、完整动作监督、课程配比及协议修订后的样本处理规则。
- `configs/sft_main.yaml` 指向主配置；`configs/sft_smoke.yaml` 显式保留旧协议用于原有 fixture 数据。
- `configs/evaluation_main.yaml`：接入同一冻结配置，默认全部 DEV_ENGINEERING，root 调用预算 64。
- `repair.py`：增加可执行的 `responsibility_filtered` 策略；原 traceback 默认值只服务已有 F4/F9
  验收与历史配置，不是主配置的待选分支。
- `dataset.py / train_sft.py`：导出 manifest 和逐样本 meta 记录双协议版本；主训练 loader 拒绝
  不匹配版本。新导出配置不能直接把旧 runtime trace 重标记为新协议。

初始 SFT 固定 NF4/BF16、LoRA r16/alpha32/dropout0.05、all-linear、8192 长度、batch1×累积16、
LR1e-4、seed42、一轮有限 root 抽样。前 20% D_IMPL/D_CONTROL=80/20，随后
D_PLAN/D_IMPL/D_COMPOSE/D_CONTROL=30/40/25/5。正式起点为公开底座，数据只能是 TRAIN。
