# PR0：规划表示适配与零更新诊断

状态：**COMPLETE（2026-09-10，TRAIN 诊断）**。完成表示适配、20 条前后自然基线，以及
50 个根状态 × 4 个候选 × 2 次续跑，共 **400 次完整候选续跑**；全部采集进程通过权重不变检查。
依据 [PRRPO 设计](../docs/决策分解改进设计_PRRPO_2026-09-10.md) 的 PR0 边界执行；
本阶段检验可执行分解与长期回报差异，不检验 RL 更新收益。

**主要发现：当前新表示下的分解偏好与执行收益明显不一致。** 根状态平均分配给 SPLIT 的选择概率为
92.64%，但 ATOMIC 在 100 次续跑中全部通过，SPLIT 候选起始的续跑为 72/300。
同时，3 个状态在已注册分解方案之间出现回报差异，显示出责任分配与执行器能力之间值得学习的关系。
当前格式支持和任务分布仍限制了细粒度 RL 的有效性检验。

机器汇总：[result.json](../runs/refinement/PR0/result.json)。

## 失败来源与责任证据

规划阶段发生 442 次 `INVALID_ACTION_JSON` 拒绝，另有未知责任 owner 6 次、无效 dataflow 4 次、
缺失责任 owner 1 次。观察到的格式问题包括固定模式前缀后重复逗号、缺少字段引号等。
所选 200 条适配示范均通过新增责任映射覆盖检查，但本次有限 SFT 尚未建立足够的生成格式支持。

固定 F01 的 child 处理阶段另有 14 次 JSON 错误、40 次未验证产物消费拒绝、4 次版本不匹配；
实现阶段有 5 次接口不匹配。以上为拒绝事件数，包含重试，不是独立计划数。
400 次续跑中，218 次在协议重试耗尽后结束；182 次形成根程序，其中 172 次通过、10 次功能失败。
仅凭根功能失败不能将错误全部归于规划器或某个 child。

400 条最终责任状态均为 UNKNOWN，确定违规数为 0；违规惩罚项本轮未激活。
功能通过不提升为完整责任已获证明，UNKNOWN 也未被当成违规负例。

## PR0 判断

**工程链路已成立，已发现条件正文价值差异；当前数据不适合直接支撑“学会更合适的细粒度分解”的 RL 效果主张。**
ATOMIC 在本轮全部 TRAIN 续跑中达到上限，而合法 SPLIT 的覆盖有限；直接优化当前回报主要会把根模式推向 ATOMIC。
这可以检验模式偏好的纠正，却不能单独证明双层信用学到了更有用的分解粒度。

进入该主张的 PR1 实验前，应先做共同的格式支持修订，并在 TRAIN 中形成有效分解能够改善根收益的任务条件。
这两项应对后续各比较方法保持一致。上述三个状态可作为正文差异的具体检查对象；双层优势的额外效果仍需同候选 B3/B4 对照验证。
本轮完成的是预定 PR0：25 次表示 SFT 更新、0 次 RL 更新；未以节点数量或深度奖励制造分解收益。

## 表示适配与自然基线

从已验收的 A6 SFT 文件选择 200 个初始规划示范：每个 TRAIN root、每种模式各 2 个，
ATOMIC/SPLIT 各 100 个；所选状态均同时允许两种模式。只重新编码既有示范，不使用候选续跑结果。
其中 SPLIT 均为根规划，ATOMIC 含 18 个根状态与 82 个中间节点状态；这里的模式平衡针对全部示范，
不表示根状态的两类示范数量相等。
模式损失为两种完整模式字符串归一化后的交叉熵；SPLIT 另计算条件正文平均 token 交叉熵。
本地 tokenizer 将 ATOMIC 编为 `[828,51793]`，SPLIT 编为 `[50,51597]`。
输入、固定前缀和宿主 ATOMIC 正文不成为正文目标。实际示范含 28,218 个 SPLIT 正文目标 token。

单 epoch，batch=1、梯度累积 8、学习率 1e-5，共 25 次 AdamW 更新；只更新规划 LoRA。
完整目标不截断，梯度检查点与可分页 CPU 张量暂存用于控制显存占用。
已检查规划参数变化、F01 参数与同输入前向不变，以及保存后的规划 adapter 磁盘重载。
这 25 次更新属于 **SFT 表示适配**，不属于 PR1 的 RL 更新。

200 个样本完整执行，共 800 个模式字符串评分 token、28,218 个正文目标 token。

## 复现命令

在仓库根目录、`audittrainer` Conda 环境运行。每个 GPU 进程只暴露一张卡；
候选采集可用 `--shards N --shard-index i` 分配不重叠的根任务，所有分片必须完成再汇总。
以下为新运行目录中的串行等价命令，已有训练目录不会被覆盖。
重新训练时须在配置中同时指定新的 `output_dir` 和 `adaptation.output_dir`，并通过 `--config` 使用该配置。
本次实际使用 4 个逻辑分片；继续本次采集须保留 `--shards 4 --shard-index 0..3` 的对应分片参数。
已完成数据只需执行最后的 report 命令即可重新汇总。

```bash
CUDA_VISIBLE_DEVICES=0 OMP_NUM_THREADS=4 python -m audittrainer.refinement_rollout baseline --label before --adapter runs/a6/train/F11_C_seed42/final_adapter
CUDA_VISIBLE_DEVICES=0 OMP_NUM_THREADS=4 python -m audittrainer.train_refinement --config configs/refinement.yaml
CUDA_VISIBLE_DEVICES=0 OMP_NUM_THREADS=4 python -m audittrainer.refinement_rollout collect --with-baseline
OMP_NUM_THREADS=4 CUDA_VISIBLE_DEVICES='' python -m pytest -q
python -m audittrainer.refinement_rollout report
```

主要产物位于 `runs/refinement/PR0/`：`adaptation/`、`baseline/{before,after}/`、
`groups/<root_id>/`、各采集进程的请求及冻结检查记录，以及最终 `result.json`。
每组保存决策 observation、模式概率、4 个候选的原始 token/概率、8 条续跑及分组优势。
