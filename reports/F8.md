# F8：新 adapter 回接同一 runtime

2026-09-07，**COMPLETE / SMOKE_ONLY**。F7 的新权重已实际用于后续推理：
独立进程从磁盘重新加载公开 Qwen3-8B 与 adapter，通过开关前向检查，并完成两个开发任务的自然模型轨迹。

## 实现

- [policy.py](../src/audittrainer/policy.py)：扩展 adapter revision、文件摘要及训练报告核对；
  读取已保存的 tokenizer，检查编码器、特殊 token 和 chat template 与固定底座一致。
  tokenizer 的保存格式可以改变，比较其编码语义。可显式加载 NF4 双重量化/BF16 底座，采用与 F7 相同的冻结参数准备。
- `LLMPolicy.check_adapter_effect`：通过共享 `prepare_prompt` 构造同一 observation 输入，
  在 eval/inference 模式执行开启—关闭—恢复三次前向；检查有限值、开关差异与恢复一致性。
  不生成动作、不消耗 runtime 的 policy call 预算，诊断开销单独保存为 3 次 forward。
- [cli.py](../src/audittrainer/cli.py)：接通 `rollout --policy sft --adapter ...`，
  支持 `--load-in-4bit`，保存 F8 身份与探针结果；通过探针后用同一份 policy 运行所有任务。
  base/SFT 参数明确匹配，错误 adapter 或探针失败返回非零，模型能力失败保留为任务结果。
- 复用既有 renderer、no-thinking template、action schema、RepairRuntime、可见 verifier 和 trace，
  所有实际生成事件记录同一 adapter 的身份。
- 新增两个有固定可见测试的 [开发任务](../data/development/)，登记到 [roots.jsonl](../data/manifests/roots.jsonl)。
  它们没有 ScriptedPolicy 轨迹，其 root/family 均独立于 F6/F7 的 SYN_FIXTURE 数据。

## 实际命令与身份

```bash
CUDA_VISIBLE_DEVICES=1 OMP_NUM_THREADS=4 /home/lc/.conda/envs/audittrainer/bin/python -u -m audittrainer.cli rollout --policy sft --adapter runs/sft_smoke/final_adapter --load-in-4bit --split DEV_ENGINEERING --limit 2 --max-policy-calls 24 --run-dir runs/f8_sft_rollout > runs/f8_sft_console.log 2>&1
```

使用用户指定的 `audittrainer` 环境，物理 GPU 1（RTX 5880 Ada）。
base 为完整公开 `Qwen/Qwen3-8B`，revision `b968826d9c46dd6066d109eabc6255188de91218`。
加载 [F7 final_adapter](../runs/sft_smoke/final_adapter/)，其权重 SHA256 为
`732482c9fcea6108ccc54a1f3aabd45c106aca72a689f055bfa29960517464a5`，与 F7 训练报告一致。

底座使用 NF4 双重量化，算子计算为 BF16；PEFT adapter 和冻结 embedding/norm/head 保持准备后的 dtype。
身份日志中的 `dtype=torch.float32` 来自首个非量化参数，`parameter_count` 是包含量化存储的张量元素数；
它们不表示全 FP32 推理或模型规模减少。固定公开底座逻辑参数量为 8,190,735,360，LoRA 为 43,646,976。

固定输入是第一个开发任务 `dev01_stable_unique` 的初始 NEW observation，
通过正式推理的 `prepare_prompt` 编码为 **1,852 个 prefix token**。
三次前向比较完整词表上最后一个位置的 logits，尚未生成动作，也没有使用目标答案。

| 检查项 | 实际结果 |
| --- | --- |
| adapter | default，来自 F7 磁盘权重 |
| 有限值 | 三次全部通过 |
| 开启与关闭的最大绝对差值 | **28.625**，大于预设阈值 1e-6 |
| 开启与恢复的最大绝对差值 | **0.0**，容差 atol/rtol=1e-5 |
| forward 次数 | 3，单独记录 |
| 生成开始前恢复 | PASS，后续继续使用同一 adapter |

输入、模型身份和指标保存在 [adapter_probe.json](../runs/f8_sft_rollout/adapter_probe.json)，
原始三组 logits 保存在 [adapter_probe_logits.pt](../runs/f8_sft_rollout/adapter_probe_logits.pt)。
这直接证明 adapter 改变了同一底座的前向结果，无需以生成文本是否改变来猜测加载成功。

## 两条自然模型轨迹

两个任务均由模型选择 ATOMIC；各运行一次，完整保留输出与终态。

| 任务 | 模型调用 | 输入 / 输出 token | 自然动作与结果 | 功能 / 责任状态 |
| --- | --- | --- | --- | --- |
| DEV01 词序去重 | 4 | 10,359 / 187 | plan → write_code → verify → finish，6 个可见用例全部通过 | PASS / UNKNOWN |
| DEV02 括号配对 | 3 | 5,170 / 217 | plan → 无效 write_code JSON → abstain，未产生可验证 artifact | 未验证（null） / UNKNOWN |

共 **7 次真实生成、15,529 输入 token、404 输出 token、1 次 verifier、6 个测试调用**。
DEV02 的代码动作在 JSON 第 451 列无法解析，host 原样拒绝并反馈；模型下一次选择弃权。
它没有进入功能测试，因此不伪造功能 FAIL 或 PASS。两个任务都计入分母。

7 条 POLICY 事件的模型身份均与 batch 身份记录完全相同，包括 F7 adapter 权重摘要、base revision、
磁盘 tokenizer 身份与活跃 adapter；动作通过同一 runtime 和 host verifier 处理。
两条轨迹均进入 TERMINAL，batch 状态为 COMPLETED，命令退出码 0。
