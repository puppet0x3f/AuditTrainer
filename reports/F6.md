## 标签与信息边界

运行前的 `f6_reviews.json` 明确审查具体源码/接口、动作摘要及契约摘要。
运行后仅把这些既定结论绑定到实际产生的 event，保存为 `supervision.jsonl`；不按 root PASS 自动生成责任标签。
运行时 functional/responsibility verdict 保持原状；离线监督范围不是把 verifier 的 UNKNOWN 改写为 SUPPORTED。

write_code 必须有匹配 root、完整契约、artifact 版本/hash 和依赖绑定的执行证据。
无独立边界审查时，测试 PASS 最多支持 FUNCTION_ONLY；默认不进入本次责任数据。
代码或契约版本改变后，旧失败不能用新版本 PASS 抹掉。依赖 selected/linked/called 检查与人工语义审查分别保留。

输入来自当时的 observation，经统一 render_messages/no-thinking 模板生成。
未来证据可以筛选标签；它不能变成先前可见证据。新增测试向后状态和私有审查 meta 放入 canary，
确认其不出现在 messages/target；人为提前放进 observation 的未来/私有证据被拒绝。
错误代码可作为后续失败状态的输入，但不作为正确代码 target；F7 再实现 prompt 的 loss mask。

每条样本保留 mode、bucket、root/family/split、run/event、来源、版本和证据引用。
同一 run/event 的拷贝不会重复加权。fixture smoke 与 TRAIN 分开导出，开发/验证/holdout/SEALED 不进入 SFT。
超长样本整体排除，不剪掉 target、源码或契约以凑足样本数。

## F5 真实模型数据的独立导出检查

```bash
  --trace-dir runs/f5_base_smoke_cpu --out data/sft/f5_function_control.jsonl \

```

这些是另存的功能/协议对照，不混入 32 条 smoke 责任数据。
