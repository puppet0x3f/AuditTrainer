# A6：一次父职责覆盖修订

状态：**COMPLETE（2026-09-09，单 seed 开发比较）**。在 `audittrainer` 环境完成一次数据修订、
140 步正式训练、40 次能力隔离与 5 次自由运行，训练/回接/聚合验收均通过。
单 child 主指标从 1/8 提高到 2/8，固定组件从 12/16 提高到 14/16；双 child 从 7/8 降到
6/8，自由任务仍为 1/5。本轮获得局部收益，尚未形成全面改善。
配置在 [a6.yaml](../configs/a6.yaml)，机器汇总在 [result.json](../runs/a6/result.json)。
A5 四组数据、模型与结果保留，修订权重单独记为 F11_C。

## 依据与单一干预

沿用 [A5 的一次聚合诊断](A5.md)，先区分模型能力问题与框架问题：

| 来源 | 已有证据 | A6 处理 |
| --- | --- | --- |
| D：分解/接口 | F11 有 4/8 个局部计划未通过 schema；被接受的计划均为 ATOMIC | 保留诊断，不同时修改 plan 数据或提示 |
| I：局部履约 | F11 固定组件失败 4/16，包含未定义函数和算法错误 | 保持局部实现监督不变 |
| C：消费/组合 | F11 双 child 通过 7/8，parent 保留汇总时仅 1/8 | 本轮唯一主要数据修订 |
| R：定位/补丁 | A5 自由运行没有实际修复尝试 | 留待 A7 的固定修复器实验 |
| SYS：框架/证据 | A5 正式 180 次运行无评分基础设施 ERROR，冻结条件保持 | 没有需要重算旧结果的已知框架故障 |

A5 F11 在双 child 组合通过 7/8，而 child 只负责 transform、parent 自己承担 summarize 时
仅通过 1/8。F01 相应为 8/8 与 0/8。源码显示遗漏父汇总、错误汇总和输出契约不符。
A4 的单 child fused 示范将 prepare 与 aggregate 一起委托，parent 仍只负责解析/格式化，
没有覆盖 parent 保留 aggregate 的组合状态。

本轮在既有 50 个 TRAIN root 上新执行一条职责重分配示范：prepare child 保持原契约，
parent 自己实现原 aggregate 算法，再按原根契约格式化。根任务、独立 oracle 和分区不变；
参考代码来自已审查的 TRAIN 来源，不读取开发题参考代码来构造训练目标。

只将新轨迹中 parent 的完整 observation → write_code 样本加入训练池。在 A5 F11 的原始
2,240 槽位顺序中，对每个 root 的父组合代码槽位隔一个替换一个，从第一个开始：
165 个父组合代码槽位中替换 96 个，涉及全部 50 个 root。其余 2,144 个槽位原样保留，
全部 plan、局部组件、consume、verify、finish 和 abstain 样本保持原样。
替换包含合法运行状态和目标代码，不在旧委托状态下奖励 parent 越界重做。

新增程序真实执行可见及 TRAIN 私有检查；责任标签还要求根契约、职责映射、child 契约、
实际依赖版本/hash/alias 和已审查实现相符。未知源码保留 UNKNOWN，检查记录标明非真人标注。

## 能力隔离结果

40 个固定条件全部完成。每格以原定全部 8 个 root 为分母，保留无程序和协议失败。

| 条件 | A5 F11 | A6 F11_C |
| --- | ---: | ---: |
| 局部 plan + 固定 E_ref | 3/8 | 5/8 |
| 固定 transform 契约 | 6/8 | 7/8 |
| 固定 summarize 契约 | 6/8 | 7/8 |
| 两 child，parent 负责解析/格式化 | 7/8 | 6/8 |
| 单 transform child，parent 另负责汇总（主指标） | 1/8 | 2/8 |
| 两 child 功能通过且源码责任证据支持 | 7/8 | 6/8 |

主指标提高 1 个 root（12.5 个百分点）：保留 `digit_sums` 的成功，新增 `absolute_ranks`。
新增成功程序实际消费 transform 返回的有序去重列表，计算 `sum(i * abs(v) ...)`，
并按当前契约直接返回 JSON 数值。本轮因此获得了有限的职责重分配收益，但没有消除该条件
6/8 的失败，也没有取得所有能力的同步提升。

具体诊断如下：

- **D：** 8 个局部计划现在均通过注册，且仍全部为 ATOMIC；3 个失败发生在固定 E_ref
  执行之后。5/8 的结果主要对应原先计划格式失败的消失，不作为主动分解能力提升的证据。
- **I：** 两组件合计从 12/16 提高到 14/16，修复了 `prefix_span` 的 transform 和
  `reverse_negate` 的 summarize 失败；`digit_sums` transform、`absolute_gaps` summarize
  仍失败。
- **C：** 双 child 的 `sorted_squares` 恢复成功，但 `reverse_negate` 与 `absolute_ranks`
  因消费状态/alias 错误未产生 parent 程序，净减少一个成功。单 child 中，`sorted_median`
  与 `sorted_squares` 已写出所需汇总计算，却仍返回 `{"value": ...}` / `{"sum": ...}`，
  违反直接返回 JSON 结果的契约；`absolute_gaps` 与 `odd_cubes` 开始写汇总算法，但计算和
  输出仍有错误；`reverse_negate` 引用了尚未赋值的 `result`。

这些案例支持一个具体判断：补充父职责覆盖能改变部分实现并带来一个新成功，但完整履约
仍取决于正确算法、精确输出契约和稳定消费。本轮不据一次开发修订声称已解决责任重分配。
单 child 的功能通过与源码诊断不被自动升级为通用责任正确标签；沿用 A5 的责任判据。
