# F9：统一 evaluator 与 APPS 接口

2026-09-07，**COMPLETE / SMOKE_ONLY**。实现脚本、base 与 SFT 的统一 root 报告，冻结第一完整程序及预算内最终产物，
并在在线决策结束后进行离线评分。该阶段验收框架完整性，不以模型能力提升为门槛。

## 实现与口径

- [evaluate.py](../src/audittrainer/evaluate.py) 复用同一 RepairRuntime、policy、verifier 与 trace。
  evaluator 逐步驱动 runtime，在 root 第一次 SOURCE_SAVED 后、root 验证前立即保存完整依赖闭包。
  每个源码版本及其绑定、契约、wrapper、捕获事件和当时成本都保存在独立目录。
  终止后再次固定当前活跃 root artifact；包括预算耗尽或弃权时已存在的产物，终止原因单独记录。
- 两个选择均在私有评分前完成。离线评分使用快照自身的 ArtifactStore，后续 child 修复、重绑定或计划重建
  不会改变首个程序。私有 suite 从在线 verifier 中直接排除，评分结果也不写回 runtime 或触发下一次模型调用。
- root/test manifest 固定源文件及用例摘要。逐 root `roots.jsonl` 保留无程序、UNKNOWN、FAIL、弃权、
  超预算、协议和基础设施错误；一个任务或模型加载出错仍保留所有已选 root 的分母。
- `FirstProgramSuccess` 和 `BudgetedSuccess` 分别统计首个/最终程序的私有 PASS，均除以全部选中 root。
  前者允许构造根程序之前的子节点局部验证/修复，并计入成本，不冒充单次模型调用 Pass@1。
- `online_cost` 包含全部调用、输入输出 token、验证、自动重放、修复和实际用例执行；
  `scoring_cost` 独立记录离线评分。均按实际执行数量计费，包括失败前已经执行的用例。
  每成功成本的分子包括失败任务；成功数为 0 时是 null（N/A）。模型加载、总耗时和 SFT 探针 forward 单列。
- [apps.py](../src/audittrainer/apps.py) 支持 JSONL 的 `id`/`problem_id`、原始 input_output 字符串或对象，
  保留原始数据、原始 split、来源 revision/ID/hash、root/family 和完整用例。
  `fn_name` 不为 null 的 call-based 任务显式拒收；官方 test 范围只能进入 APPS_SEALED。
- `stdin` 通过既有 `solve(text) -> str` 和固定 entry wrapper 适配，仍经 Bubblewrap 隔离执行。
  新的 `Suite.comparison` 区分原有 exact JSON 与 APPS 文本比较。

## APPS 数据范围

来源为 [codeparrot/apps 固定 revision](https://huggingface.co/datasets/codeparrot/apps/tree/21e74ddf8de1a21436da12e3e653065c5213e9d1)，
经 hf-mirror.com 读取 train.jsonl 的前 100 条。实际选择在模型运行前确定，为前三个 stdin 记录：
`apps_train_0000`、`apps_train_0001`、`apps_train_0002`；它们与 F8 的两个自建任务共同组成五题开发集。
原始数据和来源说明保存在 [apps_source](../data/apps_source/)，实际导入/拒收记录见
[import_report.json](../data/apps_f9/import_report.json)。3 条导入、97 条因 IMPORT_LIMIT 未收录。

检查到的这些训练记录每条只有一个完整 stdin 用例，其中可能含多个查询。
初始“一例在线、其余离线”的划分无法应用，因此在运行前显式确定 `visible_cases=0`：
原始用例全部用于离线评分，在线没有适用 suite 时返回 UNKNOWN。原始输入没有拆分或复制。
题面公开样例保留；离线样例可能已在题面或预训练中出现，不称为对模型未见的测试。
未读取官方 test 范围，已查看的这批任务固定归入 DEV_ENGINEERING。

APPS 的标准输入识别和输出比较参考 [官方 testing_util.py](https://github.com/hendrycks/apps/blob/main/eval/testing_util.py)。
`apps_stdio_legacy` 保留字符串去空白、数字容差，以及上游的集合/三位小数舍入回退。
集合回退可能忽略顺序与重复，这是该比较规则的已知宽松语义；这里的通过不代表严格输出等价，
也不将该三个任务的结果报告为整个 APPS 基准成绩。

## 实际命令

全部使用 `audittrainer` 环境；两个真实模型评测使用物理 GPU 1，完整 Qwen3-8B 的相同公开 revision、
NF4 双重量化/BF16 配置。SFT 加载 F7 `final_adapter`，其身份与 F7 训练报告核对，并执行 F8 同款开关检查。

```bash
conda run --no-capture-output -n audittrainer python -m audittrainer.cli import-apps --input data/apps_source/train_first100.jsonl --output-dir data/apps_f9 --original-split train --split DEV_ENGINEERING --visible-cases 0 --limit 3 --source https://huggingface.co/datasets/codeparrot/apps/tree/21e74ddf8de1a21436da12e3e653065c5213e9d1
conda run --no-capture-output -n audittrainer python -m audittrainer.cli evaluate --policy script --split SYN_FIXTURE --limit 6 --max-policy-calls 64 --output-dir runs/f9_script
CUDA_VISIBLE_DEVICES=1 OMP_NUM_THREADS=4 conda run --no-capture-output -n audittrainer python -m audittrainer.cli evaluate --policy base --load-in-4bit --limit 5 --output-dir runs/f9_base
CUDA_VISIBLE_DEVICES=1 OMP_NUM_THREADS=4 conda run --no-capture-output -n audittrainer python -m audittrainer.cli evaluate --policy sft --adapter runs/sft_smoke/final_adapter --load-in-4bit --limit 5 --output-dir runs/f9_sft
```

实际启动时直接使用 `/home/lc/.conda/envs/audittrainer/bin/python`，上述是同环境的等价入口。
脚本用 64 次 root 调用预算覆盖长修复 fixture；base/SFT 对同一五题开发集均使用 24 次。
脚本与真实模型的任务集合不同，本阶段不把这三组结果当作公平的能力基线比较。

## 实际结果

三组命令均完成并退出 0；16 条 root 记录的字段集合一致，base/SFT 使用完全相同的五个 root。
下表的“首个/最终成功”均为私有评分，不与在线可见 PASS 混用。

| 组 | root 数 | 首个成功 | 最终成功 | policy 调用 | 输入 / 输出 token | 在线用例 / 离线评分用例 | 总耗时 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| script | 6 | 3/6 | 5/6 | 120 | 0 / 0（脚本） | 77 / 54 | 25.28 s |
| base | 5 | 2/5 | 2/5 | 17 | 47,766 / 1,745 | 22 / 36 | 146.92 s |
| SFT smoke | 5 | 0/5 | 0/5 | 20 | 55,296 / 7,063 | 9 / 4 | 547.92 s |

脚本组 FX03 有界代码修复和 FX04 计划修订均呈现首个 FAIL → 最终 PASS，
FX05 的错误 parent 保留 FAIL。其余三个 fixture 私有评分通过；所有责任状态均为 UNKNOWN。

base 的两个自建任务通过，三个 APPS 任务没有可执行程序，终止原因为一次弃权、两次协议重试耗尽。
SFT 的词序去重生成了一个私有 FAIL 的程序，其他四题没有有效程序，五题最终均弃权。
APPS train/0 与 train/1 的 SFT 代码输出各达到 3,072 token 后被判为截断，完整输出与消耗保留。
无程序记 NO_PROGRAM，未伪造功能 FAIL/PASS 或丢弃这些任务。

SFT 的 adapter 开关探针仍为 PASS：最大 logits 差值 28.625，恢复差值 0，单独记录 3 次 forward。
这确认实际使用新权重；本次 0/5 是该 smoke checkpoint 的真实负结果，不因回接通过而被改写。
`cost_per_budgeted_success` 正确保存为 null（N/A）。所有 16 个 root 的责任状态为 UNKNOWN，保守联合成功数为 0。
